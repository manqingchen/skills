# eli5:论文/长文大白话讲解

目标不是"摘要",是**让用户真的学懂**:比喻先行、反常识点突出、读完知道接下来精读什么。全程中文,专有名词保留英文并当场解释。

## 流程(四步)

### 1. 拿到全文

按优先级尝试,成功即停:

1. **HTML 全文版**(最佳):arXiv 论文把 `pdf` 换成 `html`(如 `arxiv.org/html/2609.00006v1`),多数新论文有;一般技术文档直接就是网页。
2. **web_reader 类 MCP 工具**抓取正文( retaining 图片可关掉,省上下文)。
3. **下载 PDF** 到临时目录(`curl -sL -o /tmp/xxx.pdf`)。注意本机可能没有 pdftotext/pdftoppm,pip 受 PEP 668 限制——PDF 提不动文本时,直接把 PDF 路径交给子代理(见下一步)让它用 Read 工具分页读,别在主上下文里硬啃。

同时拿元数据:标题、作者、提交日期、页数(.abs 页或 PDF 首页),讲解开头要用。

### 2. 派子代理精读,拿结构化要点

**超过 ~30 页/大文件,绝不整体读进主上下文。**派一个只读子代理(Explore 类),给它自包含的精读提示词。模板(方括号处替换):

```
你的任务:下载并通读 <标题/URL/文件路径>,提炼结构化要点,供主代理用大白话向用户讲解。
操作建议:文件大时分块读;先提取章节标题,再按需精读相关段落,不要一次全读进上下文。
重点提取(每项给出原文依据,找不到就明确说"未找到",禁止编造):
A. 整体章节结构(标题列表)
B. 核心概念/组件定义:名称 + 一句话定义 + 文中的典型实例
C. 关键发现/论点,逐条列出(编号 + 一两句核心内容)
D. 数据/表格/基准测试结果(有就提取)
E. 反常识/与直觉相反的结论(这是 ELI5 的素材重点,单独列出)
F. 可操作的建议/方法清单(逐条短句)
G. 作者给的类比、金句(可直接引用的原文短句)
输出:按 A-G 分节的 Markdown,中文书写(专有名词保留英文),要点式、信息密度高,2500-4000 字;每节注明出处(节号/页码)。
```

### 3. 写 ELI5 讲解(这是交付物的灵魂)

写作准则,顺序即结构:

1. **先一句话定位**:这篇东西"是什么"——用"它是一份解剖报告/一本操作手册/一次实验记录"这类类别词开头,不要从背景综述开始。
2. **核心比喻先行**:给主概念找一个日常比喻(如 LLM=发动机,harness=整辆车),全文围绕它展开,比喻要能承载后续细节。
3. **发现按"反常识程度"排序**,不按论文章节顺序。用户记住的是意外,不是目录。
4. **每个抽象结论配一个具体例子/数字**("90 行就够"好于"最小实现可行")。
5. **诚实标注**:推断与论文原文分开;子代理没找到的信息写"未找到",禁止补齐。
6. **结尾给阅读路径**:只想快速掌握读哪几节/想抄作业读哪节/关心什么读哪节。
7. 篇幅:对话内讲解控制在 600-1000 字量级,深度内容放进笔记文件,不刷屏。

### 4. 落交付物

存到当前工作区,命名 `<主题>-学习笔记.md`:

- **必产**:Markdown 学习笔记 = ELI5 版 + 子代理的结构化要点(章节化),开头放元数据与原文链接。
- **PDF 副本**:来源是 arXiv PDF 就顺手复制进工作区。
- **HTML 版(本用户明确偏好)**:MD 说"看着累"是常态,主动生成单文件 HTML 学习笔记。标准 Markdown 直接用 md2html 技能转:`bash ~/.zcode/skills/md2html/build.sh <笔记.md>`(左侧目录+暗亮切换+暖色,零依赖)。需要卡片网格/步骤条等手工富化时,以 `~/Documents/workspace/go/harness-engineering/Harness-Engineering-学习笔记.html` 为模板改内容(若无此文件,按这些要点现写:左侧锚点目录+滚动高亮、暗/亮色切换且切换带 0.5s 渐变防晃眼、卡片网格、暖色低亮度配色、系统字体栈、零外部依赖)。文件名与 MD 同名。

## 红线

- 子代理的每个结论都要能追溯到原文;它说"未找到"就如实告诉用户,不要脑补。
- 讲解里引用的数字(百分比、页数、版本号)必须来自提取结果,不得四舍五入创作。
- 用户只丢一个概念名(没给链接)时:先搜权威来源拿到原文依据,再走同样流程;不要凭记忆直接开讲。
