# UI 还原(设计稿 → 代码)强制工作流

设计稿通常是自包含单文件 HTML(可能数 MB,含内联图片):**基础样式 + 媒体查询覆盖层**,
典型如 `@media(max-width:700px)`(窄屏)+ `@media (width>=1400px)`(PC,Level 4 范围语法)。
基础层覆盖中间区间且往往本身就是 PC 布局。

两大目标:**组件复用优先**(能复用绝不重造)+ **尺寸只取设计稿**(缺了先问)。
本流程受两层强制约束保护:`~/.zcode/AGENTS.md` 全局规则(每次会话自动加载)+
PostToolUse 硬校验钩子(违规的样式写入会被 exit 2 退回)。

## 硬规则(违反任何一条即违规)

1. **组件复用优先**:动手写代码前必须先盘点项目已有组件(含依赖的 UI 组件库),
   能通过 props/slot/className/主题变量适配到设计值的组件一律复用;
   只有项目确实没有的组件才做 1:1 新建。禁止重复造已有组件。
2. **禁止想象还原**:一切 UI 还原必须以用户提供的**设计稿或 HTML** 为唯一依据,
   布局、颜色、尺寸、间距、交互形态一律禁止凭记忆、经验或想象编造。
   用户没有给设计稿/HTML 时,先向用户索取,禁止「参考常见样式」「凭印象写」直接动手。
3. **PC 尺寸只取设计稿**:所有尺寸、间距、字号的 PC 值,必须从设计稿的
   `@media` PC 块和基础层提取**原始值**,禁止估算、禁止自创。
4. **缺了先问**:设计稿中没有定义的 PC 值,或已有组件无法不改内部实现就达到设计值,
   必须停下来向用户确认,禁止自行推导补齐、禁止等比放大推算。
5. **断点体系以项目为准**:实现的媒体查询断点必须优先复用项目既有断点体系
   (如项目的 media mixin / 既有 pc.scss 断点),禁止照抄设计稿断点——
   设计稿 HTML 由产品提供,其断点不保证严谨,仅作布局分层参考。
   项目断点体系与设计稿都没有的断点视为自创,禁止使用。
6. **禁止缩放 hack**:禁止 `zoom`、对 html/body/#app/#root 的 `transform: scale()`
   整体缩放,禁止用 vw 等比缩放全页冒充 PC 适配。
7. **禁止放大移植**:不得把基础层或窄屏层的值等比放大后充当 PC 样式。
8. **禁止污染公共组件**:复用组件时通过其对外 API(props/slot/className/主题)适配,
   禁止修改公共组件的全局样式来迁就单个页面;确实需要改,列入缺口问用户。

## 第 1 步:解析设计稿,生成校验清单

**不要整读设计稿文件**(可能 3MB+ 会撑爆上下文),用脚本解析:

```bash
python3 <本技能目录>/parse-design.py <设计稿.html> --root <项目根目录>
```

> `<本技能目录>` = 本 SKILL.md 所在目录(如 `~/.agents/skills/ui-restore`)。
> **不要写死某个安装路径**——技能可能只链到 `.agents` 或 `.zcode` 其中之一,写死会直接报找不到文件,
> 流程中断后很容易退化成「凭经验写样式」,这正是本流程要防的失败模式。

生成 `<项目根>/design-manifest.json`:`breakpoints` 断点白名单(= 设计稿断点 ∪ 项目既有断点,
**断点选取以项目体系为准**,设计稿断点仅参考;同时**激活硬校验钩子**拦截自创断点)、
`queries` 每条 @media 的方向与规则数、`stats` 含 CSS 变量清单。

> **manifest 是项目根的单文件,每次运行都会覆盖。** 一个需求有多份设计稿(如列表页 + 详情页)时,
> 按页面逐轮还原,并在**开始实现该页面前重新生成**——否则断点白名单来自另一份稿,钩子会误拦或漏拦。
> 需求来自 prd-to-breakdown 时,交接单里已写明「哪份稿覆盖哪些任务卡」,照那个清单分批。

## 第 2 步:盘点项目已有组件(组件复用优先的依据)

```bash
python3 <本技能目录>/scan-components.py <项目根目录>
```

得到:依赖的 UI 组件库(element-plus/antd/shadcn 等,可直接 import)、自有组件按目录
分组清单、桶文件再导出。然后**读取映射候选组件的源码**,确认其 API:
props/slots/variants/主题定制点(如 element-plus 的 CSS 变量、shadcn 的 className 透传)。

注意设计稿的样式体系:稿内是 Tailwind(大量 `--tw-*` 变量)而项目也有 Tailwind 时,
优先按项目 tailwind 配置复用工具类;项目没有则换算到项目样式体系,换算值记入对照表。

## 第 3 步:组件映射表(复用/新建的判定,落盘)

对设计稿每个视觉区块做判定,每个区块一行:

| 设计区块 | 判定 | 复用组件 | 依据 |
|---|---|---|---|
| 主按钮 | 复用 | el-button(props: size/type + CSS 变量适配圆角) | 语义与视觉均可达 |
| 议价弹窗 | 需改造 | 项目 Modal 无头部双行布局 | 需改组件内部 → 列入缺口问用户 |
| SDN 拓扑图 | 新建 1:1 | 无(依赖库也无图表组件) | 走第 4 步全量提取 |

判定标准:
- **复用**:语义匹配 且 通过组件对外 API 能到达设计值(允许包一层薄封装)。
- **需改造**:组件存在,但不改其内部实现就到不了设计值 → 影响其他页面,**列入缺口问用户**。
- **新建 1:1**:项目和依赖 UI 库都没有对应组件 → 走第 4 步全量提取。
- **不确定**:一律问用户,不许默认新建。

**映射表要落盘,并回写任务卡**:

- 来源是 prd-to-breakdown 任务时,写到需求目录 `~/.prd-to-breakdown/workspace/<Jira号>/ui-restore-mapping.md`,不进业务仓库;否则写项目根。
- 判定结果与任务卡原有结论(如「复用 X 组件即可」)冲突时,**以实际读过设计稿的一方为准**,并把结论回写任务卡;用户裁决覆盖设计稿的(如「布局复用项目既有页面,稿只校对控件」)同样回写,注明「用户确认」。
- 只留在映射表、不回写任务卡 = 下次执行仍按旧结论自由发挥,视为本流程未完成。

## 第 4 步:样式对照表(防遗漏的核心)

- **新建组件**:全量三层提取,逐条从稿内拷贝并标注来源:

| 区块/选择器 | 基础层值 | 窄屏值(≤700) | PC 值(≥1400) | 来源(稿内查询) |
|---|---|---|---|---|
| .card | padding 24px | padding 16px | padding 32px | @media(width>=1400px) |

- **复用组件**:只提取"设计值 vs 组件默认值"的**差异项**,并写明用哪个 API 适配
  (哪个 prop / 哪个 CSS 变量 / 哪个 className)。
- PC 列为空 = 缺口,进入第 5 步。

## 第 5 步:缺口确认(强制闸口 🛑)

一次性汇总向用户确认,**未答复前不写代码**:
- 设计稿未定义的 PC 值;
- 需改造公共组件的区块(说明改动影响面);
- 判定为"不确定"的组件映射。

用户答复视为设计补充,记入对照表并注明「用户确认」。

## 第 6 步:实现

- 复用区块:用组件自身体系适配到对照表的设计值,差异项按标注的 API 落地。
- 新建区块:1:1 还原,分层结构**镜像设计稿**,断点数值与 manifest 零偏差。
- 每写一个样式文件,硬校验钩子即时校验;被退回就修正后重写,
  **不许改 manifest 绕过校验**(manifest 只能由 parse-design.py 重新生成)。

## 第 7 步:双宽度截图比对(交付前必做)

用 browser-use 技能(browser-use:control-browser)打开本地实现页与设计稿 `file://` 页:

| 档位 | 视口宽度 | 对照 |
|---|---|---|
| PC | ≥1400(建议 1440 与 1920 各一次) | 实现页 vs 设计稿 |
| 窄屏 | <700(建议 375) | 实现页 vs 设计稿 |

逐区块目检:尺寸、间距、字号、颜色、断点行为(对照宽度按项目断点体系取档,
PC 档下两页面必须同时处于 PC 层)。
有偏差回到第 4 步的对照表查值修正。

## 完成前检查清单

- [ ] 全部还原依据均来自用户提供的设计稿/HTML,无任何凭想象补齐的部分
- [ ] design-manifest.json 已在项目根生成,实现断点全部来自项目既有断点体系(未照抄设计稿断点)
- [ ] 组件映射表覆盖全部视觉区块:复用项已复用、新建项有依据、改造项经用户确认
- [ ] 样式对照表完整(新建全量 + 复用差异项),每行 PC 值有来源标注
- [ ] 所有缺口(未定义 PC 值 / 组件改造 / 不确定映射)已经用户确认
- [ ] 映射表已落盘,且与任务卡结论冲突的部分已回写任务卡(来源为 prd-to-breakdown 任务时必做)
- [ ] 无 zoom / 整体 scale / 自创断点 / 放大移植 / 污染公共组件
- [ ] PC 档 + 窄屏档截图与设计稿比对通过
