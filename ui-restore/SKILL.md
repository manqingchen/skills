# UI 还原(设计稿 → 代码)强制工作流

设计稿通常是自包含单文件 HTML(可能数 MB,含内联图片):**基础样式 + 媒体查询覆盖层**,
典型如 `@media(max-width:700px)`(窄屏)+ `@media (width>=1400px)`(PC,Level 4 范围语法)。
基础层覆盖中间区间(701–1399px)。

本流程受两层强制约束保护:`~/.zcode/AGENTS.md` 全局规则(每次会话自动加载)+
PostToolUse 硬校验钩子(违规的样式写入会被 exit 2 退回)。

## 硬规则(违反任何一条即违规)

1. **PC 尺寸只取设计稿**:所有断点、尺寸、间距、字号的 PC 值,必须从设计稿的
   `@media` PC 块和基础层提取**原始值**,禁止估算、禁止自创。
2. **缺了先问**:设计稿中没有定义的 PC 值(某元素在 PC 断点下无对应规则),
   必须停下来向用户确认,禁止自行推导补齐、禁止等比放大推算。
3. **断点零偏差**:实现中的媒体查询断点必须与设计稿**数值精确相等**。
   只允许等价语法改写(`(width>=1400px)` ≡ `(min-width: 1400px)`),
   禁止增删、合并、移动断点。
4. **禁止缩放 hack**:禁止 `zoom`、对 html/body/#app/#root 的 `transform: scale()`
   整体缩放,禁止用 vw 等比缩放全页冒充 PC 适配。
5. **禁止放大移植**:不得把基础层或窄屏层的值等比放大后充当 PC 样式。
   PC 层要么取稿内 PC 块的值,要么走规则 2 向用户确认。

## 第 1 步:解析设计稿,生成校验清单(必须最先做)

**不要整读设计稿文件**(可能 3MB+ 会撑爆上下文),用脚本解析:

```bash
python3 ~/.zcode/skills/ui-restore/parse-design.py <设计稿.html> --root <项目根目录>
```

生成 `<项目根>/design-manifest.json`,包含:
- `breakpoints`:全部断点(px)——后续所有代码的断点白名单,**同时激活硬校验钩子**
- `queries`:每条 @media 的原文、方向(`min`=宽屏起点 / `max`=窄屏上限)、规则数
- `stats`:style 块数、内联样式数、CSS 变量清单(还原设计变量时从这里取)

记录断点语义(示例):`700/max`=窄屏覆盖层,`1400/min`=PC 覆盖层,基础层=中间区间。

## 第 2 步:建立样式对照表(防遗漏的核心)

对设计稿逐个视觉区块(导航、卡片、表单、弹窗……)用 grep 定位并提取,
形成对照表,**每个区块一行,缺一不可**:

| 区块/选择器 | 基础层值 | 窄屏值(≤700) | PC 值(≥1400) | 来源(稿内查询) |
|---|---|---|---|---|
| .card | padding 24px | padding 16px | padding 32px | @media(width>=1400px) |
| … | | | | |

规则:值必须逐条从稿内拷贝,标注来源;PC 列为空 = 缺口,进入第 3 步。

## 第 3 步:缺口确认(缺了先问)

汇总所有「PC 列为空」的条目,一次性向用户提问确认(AskUserQuestion 或直接列出),
**未得到答复前不写任何 PC 覆盖样式**。用户答复的值视为设计补充,记入对照表并注明
「用户确认」。不允许跳过此步 silently 用估算值填表。

## 第 4 步:实现

- 分层结构必须**镜像设计稿**:基础层 + 与稿内一致的覆盖层,顺序一致(窄屏块、PC 块的
  先后关系保持)。
- 断点写法:数值与 manifest.breakpoints 完全一致;语法可按项目等价改写
  (`width>=1400px` → `min-width: 1400px`;SCSS 嵌套媒体查询同理)。
- 颜色/圆角/字体优先复用稿内 CSS 变量(stats.cssVariables),项目已有 token 体系时
  做映射表,不凭印象写色值。
- 每写一个样式文件,硬校验钩子即时校验断点白名单;被退回就修正后重写,
  **不许改 manifest 来"绕过"校验**(manifest 只能由 parse-design.py 重新生成)。

## 第 5 步:双宽度截图比对(交付前必做)

用 browser-use 技能(browser-use:control-browser)打开本地实现页与设计稿 `file://` 页:

| 档位 | 视口宽度 | 对照 |
|---|---|---|
| PC | ≥1400(建议 1440 与 1920 各一次) | 实现页 vs 设计稿 |
| 窄屏 | <700(建议 375) | 实现页 vs 设计稿 |

逐区块目检:尺寸、间距、字号、颜色、断点行为(PC 档下两页面必须同时处于 PC 层)。
有偏差回到第 2 步的对照表查值修正。

## 完成前检查清单

- [ ] design-manifest.json 已在项目根生成,断点与实现零偏差
- [ ] 样式对照表覆盖全部视觉区块,每行 PC 值有来源标注
- [ ] 所有 PC 缺口已经用户确认(或确认为空)
- [ ] 无 zoom / 整体 scale / 自创断点 / 放大移植
- [ ] PC 档 + 窄屏档截图与设计稿比对通过
